# Lesson 58: Tool search and large tool catalogs

Select a bounded relevant tool set from a labelled catalog.

This lesson is part of **Tools and extensions**. The Python implementation is shared by
the NiceGUI screen, FastAPI endpoints and command-line exercise.

## Run it

Install the environment once with `uv sync --locked`. Then run:

```shell
uv run agent-lab lesson 58
uv run python -m agent_lab.lessons.lesson_58
```

Both commands run **offline host code**. No model is called, no API cost is incurred,
and recorded examples are labelled as fixtures rather than live SDK messages.

For the browser lab, run `uv run agent-lab serve`, then open
[lesson 58](http://127.0.0.1:8080/?lesson=58).

## What to inspect

Read the exercise, predict its evidence, then run it. Inspect input validation,
state ownership and the condition that allows the next step. A model's description
of an action is not evidence that the action happened.

The exercise is in [agent_lab/exercises.py](agent_lab/exercises.py)
(function `tool_search`, line 1142). Host contracts are in
[agent_lab/services.py](agent_lab/services.py); path and tool permissions are in
[agent_lab/policy.py](agent_lab/policy.py).

```python
@exercise("tool_search")
def tool_search(root: Path, request: RunRequest, lesson: Lesson) -> dict[str, Any]:
    catalog = [
        {"name": "orders.read", "description": "read customer orders"},
        {"name": "policy.search", "description": "search refund policy"},
        {"name": "sales.analyze", "description": "compute sales totals"},
    ]
    terms = set((request.prompt or "search refund policy").lower().split())
    matches = sorted(
        catalog, key=lambda item: len(terms & set(item["description"].split())), reverse=True
    )[:2]
    return {
        "catalog_size": len(catalog),
        "selected": matches,
        "note": "Host catalog selection is distinct from the SDK's native tool-search protocol.",
    }
```

## Live Agent SDK exercise

Copy `.env.example` to `.env`, configure `ANTHROPIC_API_KEY`, and explicitly set
`LAB_ENABLE_LIVE=true`. Restart the app and choose **Live Agent SDK**.

```shell
uv run agent-lab lesson 58 --live
```

Suggested prompt:

> Use the exercise tool to search the tool catalog.

The live profile is `exercise`. Its tools and configuration are in
[agent_lab/sdk.py](agent_lab/sdk.py). Evidence profiles expose a read-only MCP
tool; the model explains already computed evidence. They do not autonomously
perform the offline exercise. Conversation profiles send two turns on one
`ClaudeSDKClient`. Question profiles require an answer in the browser UI.

`ClaudeAgentOptions` uses Python names such as `max_turns`, `max_budget_usd`,
`setting_sources` and `include_partial_messages`. The SDK owns the agent loop;
the host owns validation, tool authority and task lifecycle. The budget option
is a threshold, not an exact billing cap.

## API and lifecycle

| Endpoint | Purpose |
|---|---|
| `GET /api/lessons/58` | Lesson metadata |
| `POST /api/lessons/58/run` | Collected JSON events |
| `POST /api/lessons/58/stream` | Server-Sent Events |
| `/api/lessons/58/ws` | WebSocket events and cancellation |

Pydantic validates the request before the run starts:

```json
{"mode": "offline", "prompt": "", "max_turns": 4, "max_budget_usd": 0.10}
```

All transports use [RunService](agent_lab/runtime.py). It bounds concurrency,
owns the producer task and closes the SDK connection in the task that opened
it. A run emits one terminal `done` event. Cancellation awaits cleanup before
releasing the run slot.

## Practice

1. Identify trusted host inputs and untrusted model or source data.
2. Change one bounded input and predict whether validation accepts it.
3. Add a failure case and explain how the host should report it.
4. Compare offline evidence with a live run without mistaking fixtures for model output.
