# Lesson 45: cloud provider routing

Lesson 45 runs five native Claude Agent SDK cloud configurations through an owned loopback proxy. Each lane receives generated, isolated credentials and a fixed model route. The host alone holds the Anthropic upstream key. The lab observes SDK initialization, cloud-format request, proxy authentication, upstream HTTP result, assistant message and terminal. It records IDs and statuses without credential values or message bodies.

The five actions are Catalog (initialize and inspect each provider without inference), Same (send the same fixed prompt through Bedrock, Vertex, Foundry, gateway and first-party formats), Auth (missing and wrong credentials followed by a valid request), Models (alias, profile and region forms) and Failures (a denied Sonnet request followed by fresh Haiku recovery). The denial has a native error terminal and no upstream inference; this SDK version did not perform automatic fallback. Bedrock SigV4 uses canonical signed bytes, and Vertex uses an owned workload-identity token exchange. Generated cloud credentials do not prove access to an actual AWS, Google Cloud or Azure account.

The portal has fixed controls, fresh consent for each paid action, two distinct diagrams and three source excerpts with Yash narration. The narrated ranges cover signature verification, bounded forwarding and native evidence evaluation. Recording identity is tied to the reviewed text, settings, complete source hash, MP3 hash and word timing hash. The clips still need independent human listening review; see [narration evidence](lesson-45-narration.md).

The final five-action live matrix passed on 6 November 2026 at `.lab-data/cloud-api-live-final/c45-cloud/<group-run-id>/report.json`. It used nine native inference queries with $0.008227 summed SDK cost fields. This is observed SDK accounting, not a reconciled bill. Direct SigV4, profile and region live variants also passed.
