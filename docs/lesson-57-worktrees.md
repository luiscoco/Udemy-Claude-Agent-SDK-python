# Lesson 57 worktree integration workshop

The fixed workshop creates a new owned local Git repository and commits `greeting.mjs` and `tax.mjs` as a known base. It adds two worktrees from that exact base and starts both workers before accepting either commit. Prepared workers write the approved fixture bytes; optional SDK workers receive only Read, Write and Edit. A PreToolUse hook and `can_use_tool` callback both compare the proposed file with the existing assigned regular file. Worktrees isolate working files, while Git objects, refs and configuration remain shared; they are not an OS sandbox.

The host checks each actual branch and base HEAD, the complete changed-path union, exact source bytes, and fixed Node assertions before it commits the assigned file. After both workers settle, it requires clean main at the base and cherry-picks the original worker commits one at a time. It records original and integrated SHAs separately, verifies the integrated source and parent chain, reruns both assertions on main and removes only clean worktrees without force. The independent criterion requires all those observations and one remaining main worktree. Failure retains the owned run for inspection; no remote is contacted or pushed.

Conflict mode assigns both workers `greeting.mjs` from the same base. The first Hello commit integrates, and the second Hi commit produces an actual unmerged `greeting.mjs`. The host records that path, aborts only the current pick and retains both original worker refs and all three worktrees. It runs no combined tests or cleanup and correctly reports needs-review. This mode is a teaching example, not a successful independent integration.

`/api/c57/code` exposes three line-anchored source excerpts. `/run` accepts only fixed mode, scenario, consent and budget fields, streams progress and a final sanitized report, and allows one active run per process. `/stop` targets the current run ID. `/runs/{id}` reloads an issued UUID from its matching owner marker and returns the retained report plus its actual byte hash with no-store caching. Recovery displays evidence; it does not resume Git or award a fresh check. The UI compares the completed stream report to the independently fetched owned report before updating the lesson check.

The free `scripts/worktrees_check.py` runs both real Git and Node scenarios, reloads the owned reports, checks exact conflict retention and unchanged dependency hashes, and reports zero SDK calls and cost. The parent-process network guard still allows local loopback used by Python's Windows event loop; it is not OS network isolation for child processes. The owned Git environment disables inherited global/system configuration, hooks, signing and terminal prompts. On this Windows host, Node 24 is installed under nvm even though its default shim is inactive; the runner chooses the installed binary explicitly.
