# Lesson 43: remote MCP and resources

The lab starts a FastMCP server on an owned `127.0.0.1` port. A protected MCP request receives a Bearer challenge, followed by protected-resource metadata, authorization-server metadata, and a short-lived local machine credential grant. Only credential labels enter reports. This fixture teaches the wire sequence; it does not certify an external OAuth provider.

The local actions make real HTTP or legacy SSE MCP client connections. `auth` checks missing and foreign tokens (401), a valid token without initialize (400), an unknown MCP session (404), and an expired credential (401). `cache` reuses a token, revokes it, confirms 401, obtains a second token, and reaches a second marker. `transports` runs both transports. `toolsets` lists the two named tools and verifies that `find_order` returns an MCP resource link. `resources` and `host-read` read a selected fixed URI and compare its content digest and length with the server handler log. The owned resources are a runbook, incident note, order template, tiny PNG, and inert HTML widget.

The live actions give `ClaudeSDKClient` only `mcp__lesson_remote__get_status` and, for resource reads, `ListMcpResourcesTool` and `ReadMcpResourceTool`. The host hook restricts tool inputs to the current fixture marker and selected URI. A passing result needs a same-ID SDK tool result, an authenticated wire request with matching connection-scoped JSON-RPC ID and marker, a server handler receipt, a real `resources/read` when selected, connected server status with the status tool in its inventory, and a successful terminal result with canonical UUIDs and finite cost. Agent tool-use IDs and MCP JSON-RPC IDs are separate. Reports contain no Bearer token or client secret.

`reconnect_mcp_server` is available in the installed Python SDK. The bounded live reconnect action verifies two tool calls on one client and one session over HTTP or SSE, using the same credential label. Python SDK 0.2.174 has no public `set_mcp_servers` method, so the live `rotate` step uses a version-guarded private `mcp_set_servers` control request. It revokes the first credential, proves it now returns 401, obtains a second grant, replaces the connected server configuration, calls reconnect, and requires the second tool receipt to carry `credential-2` in the same SDK session. This private shim must be reviewed after an SDK upgrade. A config-file rewrite alone was tested and kept the old Authorization header; a fresh SDK client would not meet the same-client requirement.

Use `/api/c43/facts` for the fixed inventory and `/api/c43/code` for three source excerpts. POST `/api/c43/{auth,cache,transports,toolsets}` accepts the strict local base input; POST `/api/c43/{resources,host-read}` adds a fixed resource and transport. POST `/api/c43/live` takes `step=tool|resource|rotate` and `mode=local|live`; local mode is a host-only protocol rehearsal. The supported Python reconnect control has an explicitly opted-in CLI smoke case, outside the pinned browser route set. `mode=live` requires fresh `consent=true`; paid calls are also gated by `LAB_ENABLE_LIVE` and private provider credentials. The browser lesson uses the same fixed action, transport and resource controls.
