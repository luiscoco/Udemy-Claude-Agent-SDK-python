# Lesson 37: Permission prompt tool

This Python lesson delegates one fixed Write decision to an owned stdio MCP gate. The installed SDK supports `permission_prompt_tool_name`; the gate tool receives the proposed tool name and input, asks a token-scoped loopback host handler, and returns one JSON text block. The host rejects a wrong run, gate, capability, input or duplicate decision. The live SDK profile also has an exact Write hook and four-turn, $0.10 thresholds.

Allow preserves the Write, Edit replaces its path and content, and Remember proposes a session rule. Deny refuses the Write; Interrupt refuses it and stops. Malformed text demonstrates that a returned string is not sufficient. The check requires a separate process receipt, correlated SDK Write call and result, successful parent terminal, normal closure and fresh matching file content. Remember was observed for one Write only; later rule reuse is not established. Prepared mode runs a real MCP client and process with a local file effect, while SDK-shaped messages are labelled fixtures.

The pinned contract calls for a Node process. Node is unavailable here, so the fixed process uses Python and the same stdio MCP boundary. The `/api/c37` routes expose run, dry plan, gate log, identity, answers, failure details and code. A manual run can hold the pending gate until `/decide` supplies one matching answer; wrong identities and duplicate answers are rejected. Narration and visual media remain open.
