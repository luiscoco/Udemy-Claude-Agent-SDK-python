# Lesson 50: synthetic support desk

The Python capstone implements the pinned `l50-lesson-50-full-stack-capstone.md` contract with Ada and Bo fixtures. Host selection scopes every conversation, order, ticket, refund and audit row. The UI selector is a classroom stand-in for authenticated identity; there is no real customer account, payment processor or CRM service.

`DeskStore` validates and atomically saves the owned JSON ledger. `DeskOperation` admits exact tool calls and requires a successful fresh orders read before the selected ticket or refund tool on every turn. `DeskApprover` binds a refund decision to its run, conversation, call and one-shot token. Denial writes audit evidence without a refund row; approval writes one 1000-cent row. Negative local cases corrupt the reported evidence after real host effects, so the evaluator withholds a passing badge.

The local route is an authored lifecycle with real persisted host effects. The native route runs the Python Agent SDK with only the selected desk tools, a pre-tool admission hook, same-session resume and actual tool call/result IDs. The CRM close forks the resumed session with no desk tools and schema-constrained output, then persists the record without modifying the transcript. Native evidence is checked against the host ledger and reported SDK cost. The shared CLI runner also uses the new desk instead of the earlier generic `support` exercise.

`/api/c50` exposes facts, source, scoped state and conversation reads, chat, pending proposal, one-shot decision, close, local evaluations, stop and reset. The NiceGUI panel uses those same routes and preserves the selected open conversation across operations and reload. The page has seven explained questions, three source-bound Yash clips and distinct concept and walkthrough SVGs.

Verification: `tests/test_desk_store.py`, `tests/test_desk_lab.py` and `tests/test_api_desk.py` cover persistence, scope, approval, negative evidence, HTTP restrictions, local close, cancellation and a transient Windows replace lock. `tests/test_learning.py::test_browser_lesson50_desk_lifecycle` covers the 390px UI path, source/audio, reload and horizontal bounds. The final full offline regression passed with 1,985 tests and 14 skips. The post-change provider-backed five-action matrix, shared-runner Orders query and approval-boundary cancellation all passed; see [live acceptance](live-acceptance.md) for receipts and measured costs.
