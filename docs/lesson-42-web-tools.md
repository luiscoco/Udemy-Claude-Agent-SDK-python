# Lesson 42: Web tools with host policy

The lesson enables only `WebSearch` and `WebFetch` for fixed Node.js research. WebSearch input is rewritten in `PreToolUse` to `allowed_domains=["nodejs.org"]`, removing a conflicting blocklist. WebFetch is allowed only for five exact HTTPS Node.js URLs. The host rejects credentials, ports, fragments, other hosts, suffix impostors and unlisted paths before the tool runs. A fixed `https://example.com/` guard attempt produces a correlated denial and no fetch completion.

The lab offers `GET /api/c42/facts`, `POST /basics`, `POST /fetch-lab`, `POST /injection`, `POST /guard`, `POST /research`, `GET /state` and `GET /code`. Request bodies permit only prepared/live mode, fresh live consent, a fixed prepared fault, and for fetch-lab one fixed page choice. Each action creates fresh per-lane work and CLI home directories. The host accepts only one active action and bounds it to 120 seconds. Read-only facts, state and code make no model or internet call.

Prepared mode writes an owned page fixture, rereads its bytes and SHA-256, invokes the actual Python policy functions on synthetic tool inputs, and labels all SDK-shaped calls/results as authored. Live mode observes real SDK call IDs, user tool-result IDs, PreToolUse/PostToolUse receipts and terminal results. A successful check requires exact action calls, same-lane same-ID results, matching policy observations and a successful terminal. A missing page and missing, foreign or failed prepared results stay **Needs review**.

The injection comparison appends one harmless, explicitly authored sentence after a real public fetch. The unguarded lane delivers it; the guarded lane replaces two known phrases with `[instruction-like page text removed]`. This demonstrates a heuristic, not complete prompt-injection protection. It does not claim that Node.js hosted the hostile sentence. Citation labels are recomputed from each lane's fetched and search-hit URL ledger. A recorded URL does not prove that its page supports a claim.
