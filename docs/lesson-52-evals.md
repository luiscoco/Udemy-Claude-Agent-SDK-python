# Lesson 52 evaluation lab

The lab evaluates three fixed Ada support cases: order lookup, ticket follow-up and a denied refund. `agent_lab/evals_core.py` owns the case manifest, five disclosed rubric criteria, three business checks, calibration, statistical comparison and the harness fingerprint. Synthetic replies are authored fixtures. They demonstrate the baseline, cold tone, false refund and repaired candidate with zero provider calls; they do not measure model quality.

The free baseline contains three trials per case. The heuristic calibration compares eight human-labelled replies across five criteria, producing 40 decisions. Its two lenient semantic misses remain visible and limit the heuristic to teaching use. Each comparison retains 24 case/criterion rates and Wilson intervals. A non-business regression fails only when its pass-rate drop is at least 0.2 and a one-sided Fisher test gives p < 0.1; weak evidence is suspect. Scope and money failures are hard failures. Agent and judge cost fields remain separate, with unknown actual cost blocking promotion.

`/api/c52/facts`, `/code`, `/baseline`, `/demo`, `/calibrate`, `/run`, `/promote`, `/pairwise`, `/active` and `/stop` expose the lab. Invalid fixed input returns 400, the disabled or unconsented paid path returns 403, missing retained runs return 404 and overlapping mutations return 409. A retained run is immutable. Baselines are scoped to synthetic/live provenance and heuristic/model judge. Promotion requires a complete three-trial-per-case report, passing business and rubric checks, known cost, the current fingerprint, an exact reviewed digest and a review note. AB/BA pairwise inspection reverses positions and discloses its local keyword preference.

The optional live path starts a fresh isolated DeskStore per trial and uses native Agent SDK support tools. It reloads host effects independently of the agent reply. A separate restricted Haiku query grades the reply against the fixed rubric. Each agent and judge call has its own cap and the total admission budget is at most $1, with fresh consent. A result with terminal error, missing cost, incomplete manifest or failed rubric cannot become the live baseline. Earlier three-case and nine-trial probes retained real replies, costs and rubric failures. The final nine-trial run passed all rubric and business checks and was promoted into the live/model baseline after review.

Run `uv run python scripts/eval.py` for the free baseline, `uv run python scripts/eval.py --demo cold-tone` for a demonstrated regression, and `uv run python scripts/eval.py --live --budget 1 --trials 1 --demo baseline` for an explicitly paid bounded probe. The CLI writes private reports under `.lab-data/offline-validation/`. The browser panel includes separate free and paid controls, an explicit paid consent box, trial and metric tables, calibration, baseline review, promotion, pairwise inspection and Stop. The lesson also has seven explained questions, two diagrams and three source excerpts.

Focused tests cover fixed statistics, strict routes, guarded CLI, injected live boundaries and the 390px browser workflow. The clean full offline regression passed with 2,000 passed and 16 skipped.
